# The update is what ships, not the machinery for finding it

<PageMeta level="Start here" time="5 min" assumes="nothing" sprite="crown" />

<ThemeToggle />

You click a button and a number next to it goes up by one. Between those two moments, most
frameworks stop and rebuild a description of the whole screen, compare it against the previous
description, and work out what actually moved. That is a lot of effort to discover that one piece
of text is different.

**Markless works that out while it is compiling your file, so the browser never has to.** The
compiler reads your component, sees which piece of text read which variable, and writes the update
directly. What arrives in the browser is the small change, not the machine for discovering the
small change.

Here is that running, on this page. Click the button once, give it a beat, then read the file
underneath and see if you can find anything in it that is not the feature:

<CounterDemo />

```tsrx
import { state } from '@markless/core';

export default function Counter() @{
	let count = state(0);

	<button onClick={() => count++}>Clicked {count} times</button>
}
```

Six lines, and four of them are things you already know: an import, a function, a variable, a
button. The only new word is `state`, and all it does is say that this variable is one the page
should follow.

## Your components run once per appearance, not once per change

Clicking that button does not run `Counter` again. It runs `count++`, and then the one piece of
text that read `count` is rewritten. The specification is blunt about what that costs at runtime:

> Steady-state interactions run at the vanilla-JS floor (the tiers ARE the
> textContent/replaceChildren calls a hand-writer would make, selected at compile time). Component
> execution is paid exactly once per appearance of content.

That quote is from `specs/framework/12-arm-rendering.md`. It is worth reading it as a promise about
your code rather than a boast about the framework: the update you get is the one you would have
written by hand, and you did not have to write it.

## One language, and you already speak most of it

Markless components are TypeScript functions in files ending in `.tsrx`. Three things look
unfamiliar the first time, and after twenty minutes nothing else will. Reading a `.tsrx` file is a
short page of its own, and it is the next thing to read.

There is no separate template language, no configuration file that decides which files are pages,
and no build step you have to learn to describe. A file under `pages/` is a URL, and a component is
a function.
