# State is a variable the page is watching

<PageMeta level="Start here" time="5 min" assumes="reading-tsrx" sprite="burst" />

<ThemeToggle />

Counting in JavaScript takes two lines.

```tsrx
let count = 0;
count++;
```

That code is correct. Put `count` on the screen, then run `count++`, and the screen will not change.
Nothing is wrong with the variable. Nothing told the page to care about it.

**`state()` is how you tell the page to care.**

```tsrx
let count = state(0);
```

It is still a `let`. It still starts at zero. You still read it by writing `count` and change it by
writing `count++`. The one difference: any part of your markup that used `count` now updates when
`count` changes.

Here it is running. Click it a couple of times, and give it a beat between clicks:

<CounterDemo />

That button is this file, all of it:

```tsrx
import { state } from '@markless/core';

export default function Counter() @{
	let count = state(0);

	<button onClick={() => count++}>Clicked {count} times</button>
}
```

`count++` is the only thing the click does. There is no update call. There is no second name for the
variable. The number inside the button is the only thing on the page that changes.

## Only the parts that read it change

That last sentence is worth being literal about. Here are two numbers side by side. The first is a
state variable. The second is an ordinary number, drawn once with `Math.random` while this component
rendered, and never touched since.

Click the button once, and watch which of the two numbers moves:

<TwoVariablesDemo />

The watched number went up. The drawn number did not. It will not, however long you keep clicking.

The two numbers are the receipt. The click did not re-run the component. Had it done so, a
fresh random number would have appeared alongside the new count. Instead it updated the one piece of
text that read `clicks`, and left the rest of the section exactly as the server sent it.

Here is the whole file:

```tsrx
import { state } from '@markless/core';

export default function TwoVariables() @{
	let clicks = state(0);
	const drawn = Math.floor(Math.random() * 900) + 100;

	<section>
		<p>A watched variable: {clicks}</p>
		<p>An ordinary number, drawn once while this rendered: {drawn}</p>
		<button onClick={() => clicks++}>Add one to the watched variable</button>
	</section>
}
```

This is the useful way to hold the idea. `state()` is not a special kind of storage. It is not a box
you have to open. It is a note to the compiler: someone is going to change this, so keep track of
who is reading it.

The error is MARKLESS_STATE_STALE_LOCAL_WRITE: Cannot write to plain from a handler because the template reads the component local only during initial render. It then tells you the fix: move the variable into state(). This is the same rule from the other side. The page can only follow what you asked it to follow. A variable that changes and is on screen has to be state." />

## What the compiler does with that note

When you write `state(0)` in a `.tsrx` file, the compiler reads your whole component. So it knows
three things before your app ever runs: where the value is created, everywhere it is read, and
everywhere it is written.

Every read of that binding compiles to a graph read. Every supported write compiles to a graph
write. That includes reads inside click handlers, inside markup, and inside helper functions in the
same file.

Two consequences you can feel:

**Your component function does not run again.** Clicking that button does not re-run `Counter`. It
runs the two characters you wrote, `++`. Then it updates the one piece of text that read `count`.
Updates belong to the value, not to the component.

**Objects update field by field.** A scalar becomes one watched cell. An object becomes one watched
cell per path. So this only updates the part of the page that read the status:

```tsrx
let user = state({ name: 'Ada', status: 'anonymous' });

user.status = 'ready';
```

## Where `state()` works

Inside `.tsrx` files. That is the rule, and it is not an oversight.

Calling `state()` from a plain `.ts` file throws immediately, on purpose. Reactivity here is a
feature of the language the compiler owns, not a library you can call from anywhere. The plain
`let` and the plain `count++` sit downstream of that line. You find out at once, rather than
wondering later why a number never moves.

## Try it yourself

Open the counter file in your own project. Add a second line of markup that also reads `count`, say
a paragraph above the button. Click once. Both places update, and you did not write anything to
connect them.
