# A link is a route plus its parts, not a string you build

<PageMeta level="Building" time="4 min" assumes="routes" sprite="arrow-curve" />

<ThemeToggle />

Six months after shipping, somebody renames a folder. The build is green and the tests are green.
One link in the footer now goes nowhere.

Nothing was watching it. It was a string, and a string is just a string.

**You write the route pattern and hand it the parts.** The link is then checked the same way a
function call is checked.

## The pattern is the file, brackets and all

```tsrx
import { Link } from '@markless/router';

export default function PostLink({ post }: { readonly post: { slug: string; title: string } }) @{
	<Link href="/blog/[slug]" params={{ slug: post.slug }}>
		{post.title}
	</Link>
}
```

That `href` is not the URL. It is the file, `pages/blog/[slug].tsrx`, written the way it is spelled
on disk. `params` fills in the one hole in it. The router builds `/blog/whatever-the-slug-is` for
you.

A catch-all works the same way. It takes a string, a number, or a readonly array of segments. The
next two examples show the element on its own. Write it inside a component of your own, with `Link`
imported the same way:

```tsrx
<Link href="/docs/[...slug]" params={{ slug: ['guides', 'intro'] }}>
	Docs
</Link>
```

A page with no holes in it needs no `params` at all:

```tsrx
<Link href="/">Home</Link>
```

## The types come from your own `pages/` folder

When the router builds, it writes two files:

```txt
markless-router-env.d.ts
.output/markless/router/types/routes.d.ts
```

Those hold the route model for your project, under names you can read in an editor tooltip:

```ts
MarklessRouterStaticPageHref;
MarklessRouterConcretePageHref;
MarklessRouterRoutePattern;
MarklessRouterRouteParams;
MarklessRouterLinkProps;
```

Then they extend the `@markless/router` module, so `Link` only accepts an `href` your project
actually has. Import `Link` from `@markless/router`, exactly that spelling. That is the module the
generated types attach themselves to.

## What a `Link` is at runtime

It renders a real `<a>` with a real `href`, so the browser treats it as a link. Middle-click opens a
tab. Right-click offers to copy the address. A reader with JavaScript off still gets where they are
going.

On a click it navigates on the client instead, and the router owns that navigation.

<Collapsible sprite="star-badge" summary="Three more props on Link" text="prefetch asks the router to start fetching the destination before the click, so the navigation begins with work already done. Its type is boolean | 'intent' | 'viewport', and the two strings are the useful part. 'intent' starts the fetch when the reader hovers or focuses the link. 'viewport' starts it when the link scrolls into view. replace swaps the current history entry instead of adding one, which fits after a form submission or a redirect, so the back button does not walk the reader into the page they just left. scroll controls whether arriving at the new page moves the reader back to the top. All three are ordinary props on Link, and all three are optional." />
