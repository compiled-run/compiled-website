# Make a file, get a URL

<PageMeta level="Building" time="5 min" assumes="components" sprite="square" />

<ThemeToggle />

Routes in a Markless project are not declared anywhere. There is no `routes.ts`, no array of path
objects, no `register()` call at the bottom of a config.

**A file under `pages/` is a URL, and its path on disk is the path in the address bar.** That is
the whole routing system. You add a page by adding a file. You move a page by moving the file.

## The whole mapping is one table

This is the required mapping:

```txt
pages/index.tsrx          -> /
pages/index.mdx           -> / if pages/index.tsrx is absent
pages/about.tsrx          -> /about
pages/docs.mdx            -> /docs
pages/blog/[slug].tsrx    -> /blog/:slug
pages/docs/[...slug].mdx  -> /docs/**
pages/404.tsrx or .mdx    -> unmatched page requests, status 404
pages/500.tsrx or .mdx    -> unhandled page rendering errors, status 500
```

Two extensions become pages: `.tsrx` and `.mdx`. Two are rejected on purpose: `.tsx` and `.jsx`.

Square brackets are the only punctuation in the whole scheme. `[slug]` is one segment, which the
page reads back at runtime. `[...slug]` is every segment underneath, however many there are.

Every one of those answers came from the file's own name. Nothing registered a route. Nothing had to

That is the point. A wrong URL and a wrong file name are now the same mistake, and you can see it in
the file tree.

## Two files, one URL, is an error you get told about

The router treats conflicts as a hard failure, and extensions do not change that. `pages/docs.tsrx`
and `pages/docs.mdx` both map to `/docs`. The build stops with a message naming both files:

```txt
Route conflict: /docs is defined by both:
- pages/docs.mdx
- pages/docs.tsrx
```

The alternative is quieter. One of the two wins silently, and production is where you find out
which one it was.

## `document.tsrx` is the one HTML page around all of them

Pages are the inside of the document. The document itself is a single file at the root of the
project. It renders `{children}` where the page goes:

```tsrx
import { Html } from '@markless/router';

export default function Document({ children }: { readonly children?: unknown }) @{
	<Html>
		<head>
			<meta charset="utf-8" />
			<meta name="viewport" content="width=device-width, initial-scale=1" />
		</head>
		<body>{children}</body>
	</Html>
}
```

`<Html>` is the root element. It is a component rather than a plain `<html>` tag, because the router
puts things in the head that you should not have to write yourself. It adds the tags for the built
assets, and the small script that applies a stored theme before the first paint.

One document, every page. There is no second shell to keep in step. There is no `layout.tsrx`
convention either.

## The parts of a page that are not pages

Four names sit beside `pages/` at the top of the project. Each one owns exactly one job:

```txt
pages/         routes
document.tsrx  the HTML around every route
public/        files served as they are
api/           request handlers
middleware/    code that runs before a request reaches a page
```

`api/` and `middleware/` are top level, next to `pages/` and not inside it. A folder called
`pages/api/` is not supported. A file there would be a page with a strange name, not a handler.

You do not write an entry file for any of this. A client entry, a server entry, a render shell and
a resume entry are not valid things for an app to author. The router owns every one of them.

## Try it yourself

Rename one of your pages, say `pages/about.tsrx` to `pages/team.tsrx`, and reload. The old URL now
answers with your 404 page, and the new one works. You changed nothing except the file's name.

Then add `pages/blog/[slug].tsrx` and visit `/blog/anything`. The page renders, and the segment you
typed is waiting in its props.
