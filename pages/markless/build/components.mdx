# A component is a function, and props are its parameters

Pages get long. The button that adds a bike wants its own file. The number it adds to wants to
stay where it is.

The usual worry is what you have to write to keep the two files in step.

**Nothing. A prop is a parameter, and reading it in the child re-reads the parent's live value.**

## Splitting a file is an ordinary TypeScript move

Here is the whole idea in two files. The parent owns the number:

```tsrx
import { state } from '@markless/core';
import BumpButton from './bump-button.tsrx';

export default function SplitCounter() @{
	let total = state(0);

	<section>
		<p class="playground-output">Total: {total}</p>
		<BumpButton label="Wheel one in" onBump={() => total++} />
	</section>
}
```

And the child owns the button:

```tsrx
export default function BumpButton({
	label,
	onBump,
}: {
	readonly label: string;
	readonly onBump: () => void;
}) @{
	<button type="button" onClick={() => onBump()}>{label}</button>
}
```

Two ordinary exported functions. The child's parameter list is its whole API.

`label` is a string it prints. `onBump` is a function it calls. If you can read a function signature,
you can read a component.

Run that pair. Pressing the button moves the number. Nothing in either file subscribes one to the
other.

The click runs `onBump`, a function the parent wrote and handed over. That function assigns to
`total`, which is a watched variable. So the one piece of text that reads `total` changes.

The child never knew a number existed. The parent never knew a button did.

## A prop is a live read, not a copy

This is the part worth slowing down for. The parent passes `label={title}`, and `title` changes
later. The child does not need to be told.

**Props are getter-backed.** Reading a prop inside the child re-reads the parent's graph. So what the
child renders is always the parent's current value.

Destructuring in the parameter list does not break that. `const { label } = props` is an alias. Every
later read of `label` still goes back to the parent. Write the parameter list you would write in any
TypeScript function.

<Callout sprite="cross" title="One shape the compiler rejects today" text="A destructuring default in the parameter list is a compile error. Writing function Badge({ label = 'stable' }) fails with MARKLESS_STATE_DESTRUCTURE_DEFAULT_UNSUPPORTED. The compiler cannot make a graph alias out of a value that may or may not come from the parent. Declare the prop without a default and pass it explicitly at every call site. Or compute the fallback inside the component with computed()." />

## Callback props are how a child talks back

There is no special event system between a parent and a child. `onBump` above is a plain function
prop, and the child calls it. That is the whole mechanism. A real app uses the same one:

```tsrx
import { state } from '@markless/core';
import Nav from './nav.tsrx';

export default function Shell() @{
	let libraryStatus = state(false);

	<Nav libraryOpen={libraryStatus} onToggleLibrary={() => (libraryStatus = !libraryStatus)} />
}
```

Name them however you like. `onBump`, `onToggleLibrary`, `commit`, `save`. The `on` prefix is a
convention for "this one is a callback", not a rule the compiler enforces.

## Nested content arrives as `children`

Sometimes the thing you want to reuse is the frame, not the contents. Give the component a
`children` prop and render it wherever the contents belong:

```tsrx
export default function Panel({
	title,
	children,
}: {
	readonly title: string;
	readonly children?: unknown;
}) @{
	<section class="panel">
		<h3 class="panel-title">{title}</h3>
		{children}
	</section>
}
```

Used like this:

```tsrx
import { state } from '@markless/core';
import BumpButton from './bump-button.tsrx';
import Panel from './panel.tsrx';

export default function Shed() @{
	let total = state(0);

	<Panel title="Bikes in the shed">
		<p>Total: {total}</p>
		<BumpButton label="Wheel one in" onBump={() => total++} />
	</Panel>
}
```

Think of `children` as a sealed envelope with an address on it. You can put it somewhere, put it
inside another envelope, or hand it to someone else. You cannot open it and count the pages.

**`children` is an opaque template projection.** Three operations are allowed: render it, wrap it,
or pass it on. Inspecting it, mapping over it, counting it or cloning it is diagnosed at compile
time rather than silently half-working.

## Where a component can live

Anywhere. A `.tsrx` file under `components/` that exports a function is a component. The file name
has nothing to do with the component name. The default export is what an importer gets.

Pages are components too. A file under `pages/` is one. It can import the components split out of
it.

## Try it yourself

Add a second `BumpButton` to the parent, with `label="Wheel two in"` and
`onBump={() => (total += 2)}`. Notice that the child file does not change at all.

Then wrap the number in its own component that takes `total` as a prop. Pressing the button still
moves it, with no wiring between the two new files.
