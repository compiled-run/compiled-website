# A component file is TypeScript with three differences

<PageMeta level="Start here" time="4 min" assumes="nothing" sprite="bookmark" />

A `.tsrx` file is mostly ordinary TypeScript. Imports are imports. A component is a function.
Types are types, and the editor checks them the same way.

**Three things look unfamiliar, and that is the whole list. It is not going to grow.**

Here is the counter file, all of it, with two of the three marked. Click each label and read the
sentence under the file:

<ThreeDifferencesDemo />

The third one is the fragment. It is not in that file at all, because the counter renders a single
element. It gets its own section further down, with its own example.


## The body is written with an at sign

A component is an ordinary function. Its body is a statement container, written `@{` and `}`
instead of the usual braces. Inside it you write ordinary statements: variables, conditions,
whatever the component needs.

The at sign tells the compiler that this function produces markup, not just a value. So it can
read the markup structurally rather than at runtime.

## The markup is a statement, not something you return

You do not return an element. You write the element in the body, on its own, the way you would
write any other statement. The compiler takes that as the component's output.

```tsrx
import { state } from '@markless/core';

export default function Counter() @{
	let count = state(0);

	<button onClick={() => count++}>Clicked {count} times</button>
}
```

That is the entire file behind the counter on the front page. It is the same text the box
above shows. The `<button>` line is a statement, like `let count = state(0)` above it. Nothing is
returned, and nothing needs to be.

## Two things side by side go in a fragment

When a component renders more than one thing at the top level, wrap them in an empty pair of
angle brackets. Do not invent a `<div>` nobody asked for.

Here is the same counter with a line of text beside the button. That is two things, so it needs the
fragment:

```tsrx
import { state } from '@markless/core';

export default function CounterWithLabel() @{
	let count = state(0);

	<>
		<p>Clicked {count} times</p>
		<button onClick={() => count++}>Click me</button>
	</>
}
```

That is the third difference. You have now seen all three.

## Everything else is HTML with holes in it

Attributes are attributes. An expression in curly braces is a hole you fill with a value, in an
attribute or in text. Spreading an object over an element works too:

```tsrx
import { state } from '@markless/core';

export default function Card() @{
	let meta = state({ id: 'hero', role: 'note', hidden: false });

	<section data-kind="card" {...meta} title="Stable">
		<p>Spread attributes</p>
	</section>
}
```

Markless supports exactly one authoring language, and this is it. There is no second template
syntax to learn later. No configuration decides which files get compiled how.
