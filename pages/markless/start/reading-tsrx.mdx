Imports are imports. A component is a function. Types are types, and your editor checks them the

## The body is written with an at sign

A component is an ordinary function, and its body is a statement container, written `@{` and `}`
instead of the usual braces. Inside it you write ordinary statements: variables, conditions,
whatever the component needs.

The at sign is how the compiler knows this function produces markup and not just a value, which is
what lets it read the markup structurally rather than at runtime.

## The markup is a statement, not something you return

You do not return an element. You write the element in the body, on its own, the way you would
write any other statement, and the compiler takes it as the component's output.

```tsrx
import { state } from '@markless/core';

export default function Counter() @{
	let count = state(0);

	<button onClick={() => count++}>Clicked {count} times</button>
}
```

That is the entire file behind the counter you have been clicking, and it is the same text the box
above shows. The `<button>` line is a statement, like `let count = state(0)` above it. Nothing is
returned, and nothing needs to be.

## Two things side by side go in a fragment

When a component renders more than one thing at the top level, wrap them in an empty pair of
angle brackets rather than inventing a `<div>` nobody asked for. Here is the same counter with a
line of text beside the button, which is two things and so needs the fragment:

```tsrx
import { state } from '@markless/core';

export default function CounterWithLabel() @{
	let count = state(0);

	<>
		<p>Clicked {count} times</p>
		<button onClick={() => count++}>Click me</button>
	</>
}
```

That is the third difference, and you have now seen all three.

## Everything else is HTML with holes in it

Attributes are attributes. An expression in curly braces is a hole you fill with a value, in an
attribute or in text. Spreading an object over an element works too:

```tsrx
import { state } from '@markless/core';

export default function Card() @{
	let meta = state({ id: 'hero', role: 'note', hidden: false });

	<section data-kind="card" {...meta} title="Stable">
		<p>Spread attributes</p>
	</section>
}
```

Markless supports exactly one authoring language, and this is it. There is no second template
syntax to learn later, and no configuration deciding which files get compiled how.
